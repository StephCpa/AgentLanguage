# 信息流标签、控制依赖与持久任务

本轮在受检 IR、Python SDK、Broker 和任务存储中加入信息流限制。数据标签与谓词证据独立：`Checked<T, P>` 说明已有绑定到该数据的检查回执，不说明可以公开数据，也不说明模型内容已经成为可信指令。实现更新日期为 2026 年 10 月 25 日。

## 标签与出口规则

运行时值为 `Value(data, receipts, label)`，其中 `label = Label(readers, taints)`。

| 分量 | 含义 | 合并规则 |
| --- | --- | --- |
| readers | 允许接收数据的接收方标识；`None` 表示公开，空集合表示不允许任何外部接收方 | 取交集，公开是合并单位元 |
| taints | 必须保留的来源或完整性标记 | 取并集 |

设标签为 `L=(R,T)`，合并为 `⊔`。公开且无 taint 的标签是最弱约束。新值、任务结果和控制上下文只能通过合并增加限制。公开不等于可信：一个公开的模型候选仍可以带有 `model:code-model`。

出口由可信工具目录声明接收方集合 `D` 和可选的允许 taint 集合 `A`。允许发送的条件是：

```text
R = public 或 D ⊆ R
A 未配置 或 T ⊆ A
```

每个接收方都必须被允许。默认接收方为 `tool:<工具名>`，不是根据工具名字推断出来的真实网络地址。部署者负责把标识对应到实际适配器及其全部数据去向；例如第三方模型服务、日志服务与持久缓存都可能是接收方。真正不向外发送的本地隔离工具可显式声明 `recipients=[]`，其完整性要求仍然生效。

默认 infer 输出带 `model:<工具名>`，observe、action、reconcile 输出带 `external:<工具名>`，check 不自动引入新的来源标记。工具可以通过 `output_label` 声明自己的输出限制，包括私密数据源。输出标签与输入及控制标签合并，不能覆盖掉已有输入限制。`accepted_taints=None` 默认接受任意 taint；仅增加标签不会自动建立一个严格完整性策略，需要为有此要求的出口配置允许集合。

所有 source 和 sink 声明属于可信目录，不由模型生成的计划安装。模型输出、观察、检查、业务动作、对账查询都经过相同出口检查。`Broker.deliver(value, recipient, accepted_taints=...)` 为宿主提供显式返回、发布或记录数据的出口检查 API。

## 语言与执行规则

新增 `restrict` 节点及 `PlanBuilder.restrict`。它只接受 Data、Candidate、Observation、Checked，保持原类型和检查证据，并合并附加标签。它不能把 Operation、Intent 或 Permit 转成普通数据。传入公开标签也不能放宽原标签。

```python
from al0.flow import Label

private = b.restrict(
    'private', request,
    Label({'owner', 'tool:local-model', 'tool:local-check'}, {'private-input'}))
draft = b.infer('draft', b.tool('local-model'), private)
checked = b.check('checked', b.tool('local-check'), draft)
```

`checked` 保留输入的接收方限制以及模型 taint。使用它准备一个面向 `tool:publish` 的动作会在授权阶段得到 `FlowDenied / AL7001`，不会为该动作预留费用或调用公开适配器。已完成的模型与检查调用仍计费。

解释器维护单调增加的程序计数器标签 `pc`。根输入标签在开始执行时并入 `pc`；子任务还继承创建时的控制标签。工具返回值、检查是否通过、operation 状态、任务完成与失败、任务结果分支及 race 决策都会影响后续 `pc`。字面量和最终返回值也带当前 `pc`，因此秘密分支选择之后返回一个常量不能消除控制依赖。

`match_task` 的分支在同一控制上下文中执行，分支内部及分支之后的工具调用都受约束。`match_business` 的常量结果继承输入状态的标签。后续实现已加入带持久选择的布尔 if 和纯表达式，其控制标签规则见 [纯表达式与持久条件分支](16-pure-and-conditional.md)。循环与异常捕获仍待扩展。

Intent 把准备时的标签写入规范化描述，标签参与 intent digest、permit 绑定和 slot 重放比对。若程序在准备 Intent 后进入更严格的控制上下文，则旧 Intent 不能被继续授权、接纳或首次派发。程序需要在新上下文中重新准备描述；运行时不在已有 permit 下静默修改描述。读取已持久化结果本身不会重新派发。

## 子任务边界和 race

每个任务持久保存两个标签：

- `control`：任务创建时的控制依赖，合并父上下文及显式输入标签。
- `upper_bound`：合并 control、所有嵌入子计划和结果分支中的工具输出声明与 restrict 标签，以及共享检查器识别出的 Operation/OpRef/Snapshot 工具来源；递归覆盖 Bundle/Variant 成员。

上界扫描所有静态分支，不依赖某次实际执行选择。子任务从 control 开始执行，所以不会仅因为稍后可能读取私密数据，就禁止此前独立的公开调用。在任务边界，Completed 结果及 Failed、Waiting、Cancelled 结果都合并 upper_bound。这样，即使私密调用失败、没有返回值，或者任务仅返回常量，其结果种类仍保留可能影响它的私密依赖。

`race` 合并所有候选任务的上界及获胜结果的实际标签。取消、失败和尚未返回的候选也计算在内。只给获胜者加标签会漏掉由其他候选状态引起的选择依赖；当前保守上界避免这种结果降级。它也会把一些实际没有读取私密数据的结果标为私密，这是明确的精度取舍。

输入记录、Completed 值和已观察 TaskOutcome 都保存标签。根输入、spawn 键及作用域键的恢复检查也包含标签，不能通过相同数据配上更弱标签恢复。TaskOutcome 的种类和标签随首次观察一同冻结；迟到响应不会把已取消或已接管任务的标签改为公开。

当前输出标签由可信契约静态声明。`Response` 不支持随返回内容任意增加未声明的动态源标签，因为任务可能在响应到达前被取消或参与 race。需要动态标签的适配器必须先提供覆盖所有可能输出的保守契约上界；细化标签协议仍待设计。

## 存储与恢复

schema 升至 8，新增 `tool_flows` 和 `task_flows`。工具版本内的流策略不可变，修改接收方、完整性允许集合或源标签必须使用新工具版本。工具 sink 策略在授权、新接纳、首次派发和显式 retry 时检查；带标签的底层 Store 调用缺少可信策略时拒绝，而不是把它当作公开调用。

任务的 control、upper_bound 与身份、输入和预算分配在同一事务内保存。标签字段写入已有值和 outcome 记录，不依赖独立的旁路缓存。公开且无 taint 的旧值记录仍可省略 label；公开 Intent 仍可省略 flow。

数据库结构支持从既有受支持版本 2 至 7 迁移，保留账本与未决责任。工具目录指纹新增 `flow_semantics=1`，防止新解释器以旧语义的程序身份继续运行；旧 run 不会仅因数据库迁移就自动变成带信息流证明的新 run。旧任务没有记录的标签不能追溯重建。旧执行应由匹配其原语义的运行时完成责任处理，或通过后续显式迁移协议处理。

上段记录最初信息流实现的版本。当前审计修复已将 `flow_semantics` 升至 2，并加入 `execution_semantics=2`；数据库仍为 schema 21。旧计划及旧已完成任务不能通过新受检入口直接恢复。handoff 的控制回执同时合并任务上界与实际结果标签，不输出内部结果记录。兼容边界与验证见[审计修复](46-audit-remediation.md)。

## 保证范围与后续问题

这是受检 IR 内的动态标签传播和出口检查，不是完整非干扰定理。可信宿主、Python 适配器、数据库和目录策略仍是可信基。直接调用 Python 回调、绕过 Broker 写日志、复制 `value.data` 到网络都不在这个库的隔离能力内。标签也不自动识别字符串中的真实秘密；未正确声明的数据源无法获得正确保护。

本地账本、任务状态及运行诊断供可信宿主使用，尚未提供逐字段标签的公共观测视图。运行时还没有覆盖终止、耗时、资源竞争和费用等侧信道的非干扰保证。race 的保守结果标签仅约束随后经受检出口导出的结果与控制依赖，不等同于完整并发安全证明。

下一阶段需补 [持久 ContextView](45-context-views.md) 和显式日志/发布协议、独立授权且可审计的 declassification 与 endorsement、一般控制流规则以及组合语义验证。当前没有任何通过 checker、成功返回或任务取消自动解密或提升完整性的操作。
