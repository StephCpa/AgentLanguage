# 组合协议模型与运行时一致性检查

本轮把祖先撤权、取消、两次尝试、一次协调器崩溃与恢复、独立业务回执及迟到收费放进同一个有界状态机，再把模型生成的调度送入真实 `Store`。检查目标是机制交互后的权限、责任和费用覆盖。它不改变语言语法、运行时 API 或数据库 schema。

## 边界与初态

初态已有一个原子接纳的操作、一个 Queued attempt、一单位费用预留、两单位根预算，以及根授权派生的 reports 子授权。操作使用子授权，撤权事件作用于根。最多再接纳一个 retry attempt，端点去重窗口和权限期限在固定时钟下始终未过期。

端点分别运行 apply 和 reject 两种配置：前者按 operation 去重业务效果，后者为 operation 固定无效果决定。每一个实际收到的请求都收费一单位，包括业务拒绝和去重重试。每次尝试有自己的费用记录；业务与费用回执可以独立、乱序到达。

协调器最多崩溃一次。未交给网络的派发票据在崩溃时丢失，已经进入网络的请求可以在协调器退出后完成。恢复从数据库读取原身份，不重新制造派发票据。模型中的撤权、取消和回执接收由运行中的协调器调用；退出期间只推进独立端点或执行恢复，没有另建一个管理员进程的调度。无法确认费用的已暴露 attempt 保留预留，未决状态不算业务完成。

## 分开的事件与实现对应

| 模型事件 | 对应实现或外部行为 | 关键观察 |
| --- | --- | --- |
| dispatch | `Store.start_attempt` 提交派发权 | 当前祖先授权、操作关闭状态、attempt 唯一派发权 |
| launch | 将本地票据交给独立端点队列 | 允许发生在派发提交之后的撤权或取消之后 |
| endpoint | 独立数据库完成请求 | 业务按 operation 去重，费用按物理请求登记 |
| retry | `Store.retry` | 新 attempt、新预留、当前授权与每操作次数上限 |
| revoke | `Store.revoke(root)` | 子授权仍存在，但不能凭它取得新的派发权 |
| cancel | `Store.cancel` | 退回 Queued 预留，保留已暴露费用责任 |
| business | `Store.business_result` | 接受迟到终态，关闭未发 attempt，不替代收费证据 |
| bill | `Store.settle` | 独立最终账单；撤权、取消、恢复后仍可结算 |
| crash / recover | 清除本地票据 / 重建 Store | 持久身份和账本不变，网络请求独立推进 |

撤权的线性化边界是提交派发权。`dispatch → revoke → launch` 是本模型和实现允许的路径；若端点需要在实际生效时撤销授权，还需端点参与的协议。不能把这种路径报告成已提交请求被成功召回。

## 不变量与反例

模型以 `F = 2 − R − C` 表示余额，守恒在此表示中由构造保证；实际枚举检查余额非负、真实外部费用受确认费用与预留覆盖、未最终结算的 attempt 保有费用责任、外部请求对应派发权、费用结算有外部收费记录，以及新工作不能绕过祖先撤权。运行时另从数据库读取各项余额检查守恒。业务和费用来自不同状态维度，避免仅检查一个自洽的本地余额。

`models/combined_audit.py` 对两种端点模式分别做 BFS，各枚举 **548 个状态、1,344 条转移**，所检查不变量均未被违反。状态数相同不表示两个业务终态相同；两种配置分别到达 Applied 与 ProvenNoEffect。

| 故意削弱的规则 | 最短目标反例 | 后果 |
| --- | --- | --- |
| 取消即退回已暴露预留 | dispatch:0 → cancel → launch:0 → endpoint:0 | 已取消操作的迟到费用无预留覆盖 |
| 重试不另外预留 | dispatch:0 → retry → launch:0 → endpoint:0 → dispatch:1 → launch:1 → endpoint:1 | 业务最多生效一次，两次物理请求仍收费两次 |
| 只检查叶授权 | revoke → dispatch:0 | 根撤权后仍取得新派发权 |

前两种变体分别还有两步的“未结算 attempt 无预留”反例。完整路径、状态和计数保存在 `models/combined_audit.json`。这些变体用于检查审计器是否能发现预期错误，不代表其他系统的合理实现。

正确模型还要求以下路径可达：两次请求独立收费；业务拒绝仍收费；排队取消退费；发送后的取消不退未结费用；协调器退出后端点完成；恢复、撤权、取消后仍接受业务与费用回执。通过这些可进展路径排除“拒绝一切所以安全”的空结果。

## 生成调度的覆盖含义

模型枚举全部可达状态，但运行时检查使用一个明确的覆盖分组，不宣称重放全部图边或全部路径。对每个可执行事件，收集三组上下文：

1. 安全上下文：祖先是否撤销、是否取消、崩溃前/退出中/恢复后。
2. 控制上下文：本地业务状态、已有 attempt 数。
3. 费用上下文：预留、确认费用、独立端点收费次数。

另收集模型图中所有可行的相邻事件对。BFS 提供见证前缀，确定性的贪心覆盖选择去除冗余调度；测试独立重算全部覆盖义务，确认选取后没有遗漏。相邻事件对指本模型中的实际状态转移，不含后续作为探针检查的拒绝和重复调用。

| 端点模式 | 覆盖义务 | 选取调度 | 执行步骤 | 实际涉及不同状态 | 实际涉及不同图边 |
| --- | --- | --- | --- | --- | --- |
| apply | 319 | 98 | 641 | 157 / 548 | 202 / 1,344 |
| reject | 316 | 96 | 630 | 156 / 548 | 199 / 1,344 |

194 条调度共执行 1,271 步，逐步比对本地业务状态、取消标记、attempt 阶段及账单、根预算、外部请求、效果和费用。另有 5,890 次历史身份重放、应拒绝操作、重复回执和重复取消检查，要求它们保持相应状态与事件数不变。生成调度本身没有随机种子，选择由图遍历顺序和明确的排序决定。

## 独立外部记录与进程崩溃

`models/combined_conformance.py` 的 Provider 只读写独立 SQLite 文件，不读取模型状态或运行时账本。它分别存储请求、业务决定、业务效果和费用记录。请求表不按 attempt 去重，因此适配器若错误地重复发送，同一 operation 的业务仍能只生效一次，但两次实际费用会暴露出来。

除逐步模型对应外，外部 oracle 直接用独立费用检查实际账本覆盖，用端点效果检查本地业务终态。两个故意破坏的测试验证：重复物理发送，以及取消暴露操作后错误退款，均被这一检查捕获。该独立性针对记录来源和实现，不表示假设独立：端点仍是假设诚实、费用上界固定的本地模拟器。

生成语料中的 crash/recover 是 Store 重建。另由 `tests/combined_protocol_worker.py` 在独立进程内 `os._exit(77)`，检查以下五个位置，每个位置运行 apply/reject 两种配置，共十个情形：

1. 派发提交后，尚未交给网络。
2. 已进入网络，尚未在端点完成。
3. 已接纳并发送重试，首个请求已在端点完成。
4. 两次请求完成且已撤权、取消，首张迟到账单提交前。
5. 同上，但账单已经提交。

测试在进程退出期间推进外部请求，随后恢复，再交付迟到业务/费用回执并重放。提交前的账单回滚，提交后的账单保持一次结算。这些测试验证进程退出和事务提交边界，不模拟断电、控制器丢写或备份回退。

## 复现与保存的证据

在项目根目录运行：

```powershell
python -m models.combined_audit
python -m models.combined_conformance
python -m unittest tests.test_combined_protocol -q
```

模型脚本保存 `models/combined_audit.json`。运行时脚本保存汇总 `models/combined_conformance.json` 及逐条证据 `models/combined_conformance.jsonl`，后者包含调度、运行配置与身份、最终运行时快照、预算、完整运行时事件及独立端点记录。调度遇到不一致即失败并报告步骤和前态，不把失败计入通过数。单元测试默认使用临时证据；CI 可通过 `AL0_COMBINED_EVIDENCE` 指定保留 JSONL 的路径，同时保存同名 JSON 汇总。

## 后续语义对应义务

本轮证据支持这个有限协议切片的状态检查和所选调度上的实现对应。接纳已经在初态完成，模型不包含接纳内部崩溃；也没有多操作竞争、预算树与任务租约、信息流、动态计划、期限流逝、授权 epoch 更新、部分或冲突账单、超过费用上界、零收费、retire、无限次恢复及进程隔离。

这些机制的既有单项测试继续有效，但不能由此宣称已完成其笛卡尔积验证。下一步可把任务取消/租约与跨任务资源责任加入组合关系，并逐步形成检查器、IR 与存储转移之间的无界证明。当前生成调度验证也不能替代同运行时 SDK 对照、真实工作负载和语言开发收益实验。
