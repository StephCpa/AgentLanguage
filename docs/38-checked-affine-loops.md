# 受检资源循环：原子交接、固定回执与恢复

状态：repeat 已支持 Budget、Operation、Bundle 和仿射 Variant 状态，接通共享 IR、SDK、源码前端、任务传递及解释器恢复。数据库版本为 schema 19。设计依据见 [仿射循环状态](37-affine-loop-state.md)。

## 类型与作用域

循环体必须接收 `index: Int` 与 `state: S`，并返回完全相同的封闭类型 S。希望在不同轮次携带不同资源形状时，可使用同一个 Variant 接口，例如 Deferred 携带 Intent/Permit/Budget，Accepted 携带 Operation/Budget。

repeat 消费仿射初值并产生新的状态引用，零轮也遵循同一规则。父计划不能再使用初值，也不能忽略最终状态的处理义务。若初始 Operation 仍有未处理 Snapshot，必须先处理该快照，才能把操作移入循环。

固定捕获继续要求可复制的数据或证据；跨轮资源须放入 state。纯函数仍拒绝资源循环。裸 Permit/Intent 不作为循环返回类型，依赖型许可应与对应 Intent 一起封闭在 Bundle 中。Cap 可随资源包传递，单独的 Cap 状态不在本阶段支持范围内。

SDK 沿用现有泛型 `repeat` 接口；Budget 结果保留 `Ref[Budget]`，Variant 保留类别，具体载荷和仿射规则由共享 IR 检查。源码沿用 `repeat(count, limit, initial, body, captures)`，无需新增语法关键字。

## 入场与每轮提交

资源仍由 Root 或 Task 持有。每次循环边界交接增加实际资源的 generation，不增加新的责任主体。Bundle 和 Variant 沿用现有字段路径编码，只枚举实际分支的资源，并拒绝重复引用。

入场事务同时验证当前引用、移动代次、写入首次状态和 index=0。即使循环次数为零，也会产生固定入场回执，初值因此不能再次用于新的资源操作。实际选中空资源分支的仿射 Variant 仍保留接口级消费义务与完整循环记录。

每轮返回后，在同一事务中验证当前游标、状态接口、资源 owner/代次与任务 lease，增加返回资源的代次，并写入下一游标和完整状态。循环体可以消费旧资源、创建新的资源，再返回同一接口下的不同资源清单；不要求每一轮保持相同 resource ID。

`loop_frames` 保存当前状态与游标，新增 `loop_resource_receipts` 按 `(run, activation, node, step)` 保存每次交接的来源记录和接收记录。step=-1 为入场，其余为已提交轮次。

入场重放沿用第一次固定的数据、count 和捕获，同时核对实际资源路径、身份与初始代次；不会将另一批资源绑定到旧循环。旧轮次提交重放则返回该轮的固定接收回执，核对原返回记录，不读取后续轮次的最大代次来“修复”旧引用。

数据循环保持原协议，并拒绝借该入口引入资源记录。数据协议和资源协议不能互换恢复同一个循环身份。

## 恢复、嵌套与取消

循环体使用包含 index 的稳定程序路径。游标提交前恢复会重建同一轮，复用其已有调用、任务发布和接收；游标提交后恢复从下一轮开始，跳过已经完成的循环体。解释器仅从固定回执登记资源引用，不查询当前代次来刷新历史值。

嵌套循环和每轮子任务各自拥有独立身份与回执。测试覆盖预算经过子任务后回到循环，以及嵌套循环结束后外层提交。最终状态被下游消费后，重放可以读取历史状态以重建既有节点，但旧代次不能支持新的资源变更。

取消由原 Task 责任接管机制处理。提交前取消会使旧 worker 的新提交失败；提交后取消会接管新代次。两个时序均核对没有遗留 Task 持有的 Live 资源，并保留已发生调用的确认费用。

标签随状态、循环次数和捕获传播。恢复跳过旧轮次时，仍合并持久状态的标签，不能因跳过正文而丢失先前的保密性或完整性限制。

## 执行与验证

```powershell
python -m examples.affine_loops
python -m unittest tests.test_affine_loops -q
```

[源码](../examples/affine_loops.al0) 与 [SDK](../examples/affine_loops.py) 的三轮示例生成相同 IR。每轮把同一预算转交子任务，子任务从该预算支付一次模型调用，再将预算返回父循环。独立 SQLite 端点记录 index=0、1、2 各一次调用及费用，总确认费用 3，可用余额 7，重放新增事件 0。示例也记录入场与三次迭代回执，见 [执行报告](../models/affine_loops_example.json)。

43 项专项测试全部通过，用时 37.392 秒。覆盖零轮、单轮、多轮、预算身份替换、Permit/Intent 到 Operation 的分支变化、独立 Operation 和 Bundle、空资源 Variant、标签、静态初值消费、结果遗漏拒绝、资源捕获拒绝、固定回执、旧引用拒绝、数据快照冻结及取消前后两个时序。

其中 13 项使用真实进程退出，覆盖入场及迭代的资源移动、事务提交前后、子任务发布和接收前后、schema 18 到 19 迁移提交前后。恢复后每轮只出现一次端点调用和一次收费。

SDK 类型验收包含 23 个基础计划、6 个生成绑定计划，公共方法仍为 56 个，33 + 12 个静态负例保持通过。源码目录之外安装 wheel 后，两轮预算循环通过执行与类型检查，确认两次调用/收费且重放新增事件为零，见 [安装包报告](../models/sdk_wheel_audit.json)。完整回归 829 项全部通过，用时 526.405 秒，见 [回归日志](../models/affine_loops_full_regression.log)。整体范围及后续工作见 [实现状态](08-implementation-status.md)。

## 剩余范围

固定次数、有上限的 repeat 已可携带上述资源状态；按业务结果提前 break、动态 while 和单独能力状态尚未实现。[可继续执行的推理 Waiting(Operation)](39-inference-progress-and-observation.md)、接纳层结果、ContextView、授权解密/完整性提升、受检动态计划、完整模型对应与真实工作负载对照仍在总体目标中。

本轮验证不构成任意嵌套执行的完整守恒证明。已有有限模型尚需纳入循环游标与交接回执，并建立与当前实现的对应关系。
