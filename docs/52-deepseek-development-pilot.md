# DeepSeek 开发预实验

本轮将真实 DeepSeek API 接入[生成与修复记录器](51-generation-repair-journal.md)。用户授权使用本机环境变量中的 API，优先 DeepSeek，并将本次预实验全部调用的总费用上限设为 1 美元。密钥仅在本地发送请求时读取，没有复制到仓库或 CI。

## 冻结配置与材料

配置位于 `experiments/deepseek_pilot_v1/profile.json`。选择 `deepseek-flash`，关闭 thinking，temperature 为 0，输出上限 4096 tokens；每组最多三次尝试，各有 0.50 美元预算。生成顺序预先固定为 SDK、AL-0，修复沿用该顺序，仅对未通过组继续。这是一个公开开发任务的流程预实验，没有随机化和独立测试集。

2026-10-26 实际 `/models` 响应列出 DeepSeek-V4.1-Flash；[官方价格页](https://api-docs.deepseek.com/quick_start/pricing/) 将 `deepseek-flash` 对应到 DeepSeek-V4.1-Flash-1017。API 接受的是可变别名，不能声称锁定了不可变权重版本；报告保留每次响应中的 model 与请求 ID。若观察到响应模型标识发生变化，停止继续调用。

`shared.txt`、`al0.txt`、`sdk.txt` 保存完整材料。共享说明相同；两组都介绍请求、授权、接纳、观察、穷尽匹配、查询、运行时分支及恢复，且各给一个不执行业务操作的纯分支示例。AL-0/SDK 说明分别为 2558/3050 字符，共享说明为 1897 字符。它们按概念匹配，不声称 token 数、先验熟悉度或教学难度完全等价。两组均获得相同任务 JSON、Catalog 与生成绑定，没有提供任务参考答案。

任务为 `conditional-release`：运行时 enabled 为 false 时不执行工具并返回 Skipped；为 true 时发布、查询并返回 Published。每份提交在 disabled、enabled、回复丢失、发布后进程退出四个场景中评分。它只属于一个 Git 工作流任务族，场景和轮次不是独立开发样本，也不构成完整代码修复基准。

## 计费与发送

`scripts/deepseek_pilot.py` 在请求前先登记轮次和持久派发标记，然后向固定 HTTPS 端点发送一次。重定向与自动重试关闭。响应完整保存后才导入记录器；连接中断后保留全额预留，不假定调用免费。已有响应可以重新 ingest，但不会再次发送 HTTP 请求。

按核验时公布的高峰价：未缓存输入 0.30 美元/百万 tokens，输出 1.20 美元/百万 tokens。初次预约按模型整个 1,048,576-token 上下文窗口及 4096-token 输出计算，单请求预留 0.319488 美元。收到合法 usage 后，全部输入继续按未缓存高峰价计算，缩小未知费用的预留；不会利用缓存或低峰折扣提前释放更多额度。两组预留与已结算之和受各自 0.50 美元限制。

这个推算依赖所记录的提供方 token 用量及冻结价格契约，不是提供方账单查询。实际账单总额保持未知，推算上界单独报告；不能把它写成已经支付的精确费用。提供方用量超过模型/输出上限时不缩小预留，并停止后续调用。配置变更也会在发送前被拒绝。

## 分离生成和执行

本机负责调用模型。GitHub CI 没有模型凭据，只读取已经捕获的响应，通过已有 Docker 构造边界运行 SDK/AL-0，再用共享 IR、真实本地 Git 端点和独立 oracle 评分。容器构造不挂载宿主状态或凭据，生成的 Python 不在工作区直接执行。

为固定工具 scope，在 Linux 下预建 `/tmp/al0-deepseek-pilot-v1/tasks`。CI 在相同路径重建确定性的 Git 对象和任务包，逐文件核对 participant 内容后才评分。源程序不因端点路径改变而被宿主改写。输出只做既有文件前端的换行规范化；代码围栏、语法错误或错误返回值均交给正常检查器处理。

`captured.json` 保存原始模型响应、实际提示、配置信息及轮次；`transport.json` 保存不含认证头的实际请求体与派发/完成时间。CI 原始报告由宿主读取后，核对请求 ID、前端、源码摘要、Catalog、契约及所有场景，再导入记录器。传给下一轮模型的是规定的诊断反馈，参考答案不会进入修复提示。

## 验证与结果

发送前的适配器及记录器联合测试 17 项通过（18.601 秒），覆盖未知费用、合法用量缩小预留、超界用量、超时不重试、配置漂移、回执重读和远端报告身份检查，日志为 `models/deepseek_pilot_unit.log`。

六次真实请求均取得响应，共 44,466 个输入 tokens、3,040 个输出 tokens。按上述高峰未缓存价计算，费用上界为 **0.0169878 美元**，低于 1 美元总上限；实际账单金额仍未知。达到每组三次的预设尝试数后停止生成，没有为取得成功继续增加轮次。

| 组别 | 原样源码首次通过 | 原样源码三次内最终通过 | 共同围栏提取后首次通过 | 共同围栏提取后三次内最终通过 |
| --- | --- | --- | --- | --- |
| AL-0 | 0/1 个任务 | 0/1 个任务 | 0/1 个任务 | 0/1 个任务 |
| 强 SDK | 0/1 个任务 | 0/1 个任务 | 1/1 个任务 | 1/1 个任务 |

AL-0 三次输出逐字相同，将运行时变量写成 `{commit: commit}` 的 JSON 字面量，均被解析器拒绝。SDK 三次都返回带 Markdown 围栏的代码，原样源码被 mypy 拒绝；第二、三次输出相同。模型修复阶段只收到先前输出与规定的检查诊断，没有获得参考答案或人工补丁。

观察到包装格式错误后，另加**事后的共同单围栏提取敏感性分析**：对两组使用同一函数，仅当整个输出是一个完整代码块时去掉外层围栏，保留代码内容，不提取混合说明或多代码块。它不改主轨道记录、不增加模型调用、不为模型合成修复。SDK 每份提取后的程序均通过四个场景；AL-0 没有围栏，复用其原样评分。这表明 SDK 的原样失败主要来自响应包装，不能将它当成 SDK 语言或协议失败。

三轮评分来源分别是 [40333878068](https://github.com/StephCpa/AgentLanguage/actions/runs/40333878068)、[40335303636](https://github.com/StephCpa/AgentLanguage/actions/runs/40335303636)、[40336469673](https://github.com/StephCpa/AgentLanguage/actions/runs/40336469673)。原始报告为 `models/deepseek_pilot_round1.json` 至 `round3.json`，研究汇总与请求数口径见 `models/deepseek_pilot_summary.json`。后续 CI 会重复评分已捕获源码，这些重复执行不算新的模型尝试。首次 CI 的报告汇总器曾因小数时间戳处理失败，修正后重评相同输出；该基础设施故障没有记作语言错误或新生成轮次。

这只是一个公开开发任务、固定生成顺序及非 thinking 配置下的观察。四个场景没有让查询返回 Pending/Unknown/NoEffect；SDK 程序最后返回常量 Published，因此现有通过结果不能证明所有未确认状态下的报告行为。后续应补这类场景，明确共同的输出提取协议，并为动态记录构造补齐材料和带源码位置的精简诊断。主结果和事后分析均不支持普遍语言优劣、显著性或 pass@k 结论。
