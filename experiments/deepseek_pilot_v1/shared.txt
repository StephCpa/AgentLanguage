Implement the public task using the supplied fixed tool catalog. Both languages compile to the same checked IR and use the same durable runtime. This is a public development pilot, not a hidden test.

Tools are host-owned. Program code constructs a checked workflow, not direct I/O. The host provides grants, budgets, runtime inputs and recovery. Never use files, network calls, subprocesses or a private runtime to perform the task yourself. The requested commit is an exact string. The other approved commit is not interchangeable with it.

An Intent binds the tool and request; authorize returns a Permit; admit consumes that Permit and produces an Operation. Awaiting an admitted Operation yields a business snapshot; it is not a general success assertion. Every snapshot must be consumed by exhaustive match_business before the plan finishes. The five outcomes are Applied, ProvenNoEffect, Pending, Unknown and NotDispatched. Map each to an explicit Text value. A query registered to reconcile an action takes that action's Operation, and produces a separate business snapshot which must also be matched. Matching a snapshot does not itself repeat a publication. Operation references may be used to await and then reconcile. The host will not add a missing query.

Use a runtime Bool workflow parameter for a task that requires one. Selecting a branch during Python construction is not a runtime conditional. Runtime branches contain complete checked workflows, return the same data type, and declare/pass any captured inputs explicitly. Variables/node names are unique within a workflow. Returning a string does not prove that the external goal was met. The host scores external Git state, reconciliation, resource settlement and replay separately. Submit the complete single source file with no Markdown fences. The runtime handles persistence; do not manually resend an action on restart.
